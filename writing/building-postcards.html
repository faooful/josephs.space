Writing

Building Postcards, a passive collection of whimsical stories.

Impulse

I wanted to make a place where the little stories agents tell could accumulate without asking me to do anything.

Not a transcript viewer. Not a dashboard of agent activity. Something quieter than that: a passive collection of fictional postcards, written after a session and left waiting until I feel like opening one.

That was the impulse behind Postcards.

The first version was basically a folder of Markdown files and a page that could read them. Which is still more or less what it is. The work was in figuring out how to make a passive archive feel inviting: something that could keep collecting while I was elsewhere, then offer up a strange little place when I came back.

Collection

The point is not to clear an inbox. It is to return later and find that the shelf has quietly grown.

Source

The local Markdown files are the source of truth. Each postcard has a title, a date, a sender, a short public-safe reference, and a fictional body. The browser reads those files at build time, turns them into a correspondence collection, and renders the text as text rather than letting arbitrary HTML leak into the page.

That constraint is useful. It keeps the project legible. There is no database, no sync service, no API key, and no hidden ingestion pipeline. A new note is just a new file. You can open it, read it, edit it, and decide whether it should ever leave the machine.

It also makes the boundary between the agent and the archive much clearer. The writer can leave a file behind. The collection still belongs to the person who keeps it. That separation is what lets the system stay passive: the agents add to the pile, but they do not decide how much attention the pile deserves.

Stamp

The stamp was the part that made the project feel like a place rather than a list.

I wanted every note to have a little visual object attached to it, but I did not want to generate a new image every time the page loaded. So the artwork is local and deterministic. The postcard's id and story choose a motif, palette, pose, and a small amount of variation. The same postcard gets the same drawing again.

There are doors, lanterns, piers, birds, flowers, kites, teacups, trees, mushrooms, mountains, moons, umbrellas, balloons, books, keys, clocks, bicycles, cats, and fish. Twenty tiny families is enough to make the collection feel varied without making the archive dependent on a model call for its own decoration.

The stamp is not an illustration of the story in any literal sense. It is more like a recurring bit of handwriting.

Postmark

Each note has just enough context to feel found: a title, a date, a sender, and a small story from somewhere that does not exist.

Motion

Once the stamps existed, they needed a little life, but the obvious version was too much. A page full of endlessly moving objects turns into a screensaver very quickly.

So the motion is intentionally small. Selected SVG details alternate between poses. The stamp can lean towards the pointer, with the tilt capped at ten degrees. Keyboard focus gets a fixed tilt. Reduced-motion preferences remove both. Offscreen stamps and hidden tabs pause their scenes.

Those details sound minor, but they changed the character of the page. The stamps feel present without asking to be watched. That is probably the right energy for a collection you are meant to forget about until it has something good waiting in it.

Reading

The main design problem was not writing the postcard. It was making the act of stumbling across one feel good across a desktop and a phone.

I tried a Blue Airmail direction, then backed it out. It was a useful detour because it clarified what the collection did not need. The page did not need to perform nostalgia at full volume. It needed a strong list, a readable correspondence view, and enough room around the words for the fiction to breathe.

The final shape is quieter: browse the collection, select a title, read the note, move to another one. There is no feed trying to keep you scrolling and no notification asking you to catch up. On smaller screens the navigation changes rather than simply shrinking, so the reading surface stays the thing you came for.

Carry it

The mobile version keeps the same rhythm: a small mark, a title, and a story that can be read in one quiet sitting.

Guardrails

The project is also a small exercise in making agent output safe to keep around without turning the collection into a moderation console.

The writer validates the required fields and the shape of the Markdown before saving. The build checks the collection again. Privacy checks block recognizable private patterns, but they are not treated as magic; the instructions still ask for a human inspection before anything is committed or pushed.

That balance matters. Automation can catch malformed structure and obvious mistakes. It cannot decide whether a particular detail should become public. The person holding the archive still has to make that call.

Deployment

The deployment is deliberately boring. The repository builds with Vite, runs its validation and TypeScript checks, and publishes only dist/ to GitHub Pages. There is no server to keep awake and no collection service to trust.

That simplicity is part of the product. New postcards appear locally first. Publishing is manual. The source files remain understandable even if the website disappears. The archive has a home on the web, but it does not depend on the web to exist.

I like that the technical architecture makes the emotional premise more believable. These are small notes. They do not need a large machine behind them. They can arrive, settle, and wait.

Where it landed

Postcards started as a way to save a few fictional messages and became a passive collection: local files, generated stamps, responsive reading, validation, and a publishing boundary that stays visible.

The interesting part was not making agents write postcards. They can do that easily enough. The interesting part was giving the stories somewhere to wait without making them feel like logs.

There is a difference between storing output and keeping a collection. The first one is an archive problem. The second one has taste in it: what gets a title, what gets a stamp, what gets left private, what is worth returning to when you have five spare minutes and want to visit somewhere impossible.

Now there is a quiet little page of correspondence sitting in the browser, slowly becoming stranger and more complete without demanding much from me.

That feels like enough.
